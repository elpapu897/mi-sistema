# GONVRA — Fase 1: auditoría de bloqueantes de TIENDA

Fecha: 2026-08-17 (ART)
Modo: auditoría / borrador, solo lectura.

## Resumen ejecutivo

La tienda pública responde, pero todavía no está lista para recibir tráfico pago:

1. **Checkout y cobro con tarjeta — CRÍTICO:** la última prueba aislada de checkout mostró tres pasarelas: `paypal`, `Mercado Pago Checkout Pro` y `Credit/Debit card by PayPal`. La última puede verse como “Pagos con tarjeta de crédito y débito”, pero sigue siendo PayPal. No se hizo una autorización real ni se confirmó una compra con tarjeta.
2. **Píxel y medición — CRÍTICO:** la fuente pública actual muestra `3919766821491073` y no muestra `26889872433954472`. Esto confirma una desalineación con el dataset de referencia documentado, pero no alcanza para decidir cuál borrar ni para probar que los eventos estén llegando correctamente a Meta.
3. **Política de envíos — ALTO:** el enlace que usa el footer devuelve HTTP 404.
4. **Contacto — ALTO:** la página de contacto carga, pero la consulta DNS realizada no devolvió registros MX para `gonvra.com`; no hay evidencia suficiente para tratar `contacto@gonvra.com` como canal operativo.

No se gastó dinero, no se publicaron cambios, no se tocaron campañas, no se instaló nada y no se envió ningún mensaje. No se preparó una copia de tema porque en esta ejecución no hubo acceso administrativo seguro para duplicar y subir archivos; tampoco corresponde inventar el texto definitivo de políticas sin datos aprobados por Matías.

## Evidencia verificada

### Sitio y enlaces públicos

Consulta de solo lectura ejecutada el 2026-08-17:

- `https://gonvra.com/` → HTTP 200, 134.324 bytes.
- `https://gonvra.com/pages/contact` → HTTP 200.
- `https://gonvra.com/policies/refund-policy` → HTTP 200.
- `https://gonvra.com/policies/shipping-policy` → HTTP 404, título “404 No encontrado – GONVRA”.
- `https://gonvra.com/products.json?limit=250` → HTTP 200. Se usó únicamente para confirmar que el catálogo público está vivo; no se toma ningún producto o precio como recomendación.

La página de contacto carga, pero eso no demuestra que el correo del dominio reciba mensajes. La consulta de registros MX de `gonvra.com` no devolvió resultados.

### Checkout

La Guardia y el Tester hicieron una prueba aislada con carrito: se agregó una variante pública, se abrió el checkout en ARS y se detuvo el recorrido antes de datos personales, pago y compra. El checkout final cargó HTTP 200.

Métodos expuestos en esa prueba:

- `paypal`
- `Mercado Pago Checkout Pro`
- `Credit/Debit card by PayPal`

La evidencia prueba exposición de métodos, no que el cobro falle en todos los casos. El riesgo concreto es que una persona argentina elija la opción que parece tarjeta común y termine en una integración de PayPal no validada para este flujo.

### Píxel

En la fuente HTML pública actual de home, contacto, política de envíos y política de reembolso:

- aparece `3919766821491073`;
- no aparece `26889872433954472`;
- aparece una referencia textual a `PageView`.

La ausencia del segundo ID en HTML no descarta una carga condicionada o server-side. Tampoco permite confirmar `ViewContent`, `AddToCart`, `Purchase`, CAPI ni deduplicación. No se debe borrar ningún dataset sin revisar primero Events Manager y el lugar exacto de inyección.

### Señales adicionales que agravan la fricción

La auditoría legal encontró que la política de reembolso visible dice 30 días y deja el texto `[INSERTAR DIRECCIÓN DE DEVOLUCIÓN]`, mientras el contexto comercial documenta una garantía de 10 días. También se observó que la home usa `contacto@gonvra.com`, mientras otras políticas usan `gonvra0@gmail.com`. Estos puntos no se corrigieron.

## Impacto estimado en pesos

- **Gasto de pauta observado en esta auditoría:** $0. Las campañas informadas en el contexto están pausadas; no se atribuye una pérdida histórica a estos hallazgos.
- **Checkout:** el CPA sano objetivo documentado es de $5.000–$7.000 y el ticket esperado es de $20.000–$32.000. Como escenario, 10 intentos de adquisición que llegaran al checkout y fallaran pondrían en juego aproximadamente $50.000–$70.000 de costo de adquisición y $200.000–$320.000 de facturación bruta potencial. Es exposición hipotética, no gasto ni ventas perdidas medidas.
- **Píxel:** no se puede cuantificar una pérdida sin gasto e Insights actuales. El riesgo es asignar pesos a señales incorrectas y no saber qué anuncio genera una compra.
- **Política y contacto:** no hay sesiones, abandonos ni consultas medidos para calcular una pérdida honesta. Cada consulta perdida puede equivaler a un pedido del catálogo vigente, pero no corresponde convertir ese riesgo en una cifra sin volumen.
